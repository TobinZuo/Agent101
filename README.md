## 这个仓库记录什么

围绕一个问题持续展开：**怎样让 Agent 在明确的边界内，稳定、可控地完成真实任务？**

- **原理与架构**：Agent Loop、工具调用、规划、状态管理与任务编排。
- **上下文与知识**：Context Engineering、Memory、RAG，以及信息如何进入和退出上下文。
- **工程与运行**：评估、追踪、持久化、故障恢复、权限、成本与延迟。
- **项目与实践**：源码阅读、最小复现、方案对比，以及真实场景中的经验和教训。

首页提供中英文版本，专题笔记与实验将逐步补充对应翻译，保留必要的英文术语。优先解释机制和取舍，再讨论具体框架；每篇内容尽量关联原始资料、实验或运行证据。

## 学习与实践路线

每个阶段争取留下三样东西：一篇解释、一份可运行示例、一组验证结果。

| 阶段 | 实践目标 | 验收方式 |
| --- | --- | --- |
| 01 · 跑通最小闭环 | 实现包含模型调用、工具执行和退出条件的单 Agent | 能完成预设任务；工具失败和步数超限时能结束 |
| 02 · 引入知识与状态 | 加入检索、会话持久化和上下文管理 | 能跨轮使用信息；能解释检索结果与回答的关系 |
| 03 · 建立评估基线 | 固定任务集，记录成功率、调用次数、成本和延迟 | 同一任务集可重复运行，能比较两次改动 |
| 04 · 提升可靠性 | 加入重试、超时、恢复和有副作用操作的权限控制 | 模拟工具异常后能按预期失败或恢复 |
| 05 · 探索复杂编排 | 比较单 Agent、固定工作流与多 Agent | 用相同任务集说明收益、额外成本和适用边界 |
| 06 · 完成真实应用 | 选择一个研究、编码或浏览器任务形成完整案例 | 有使用说明、运行记录、评估结果和已知局限 |

## 如何记录一项学习或实验

新内容可以从下面的模板开始，按实际需要删减：

```markdown
# 主题名称

## 问题与背景
要解决什么问题？适用场景和边界是什么？

## 核心机制
关键概念、执行流程、状态与接口是什么？

## 实现与复现
使用的模型、依赖版本、配置、数据和运行命令。

## 结果与证据
任务是否完成？成功与失败样例、执行轨迹、成本和延迟。
涉及方案比较时，说明基线、样本量与评估方法。

## 取舍与局限
哪些判断来自实验？哪些只是推测？还有什么未验证？

## 参考资料
原始链接、阅读日期，以及引用或改编的来源。
```

记录时遵循几个约定：

- **区分事实与判断**：资料中的结论、自己的理解和实验结果分别写清楚。
- **保留失败案例**：说明触发条件、错误表现、定位过程和修复办法。
- **比较需要基线**：尽量固定任务、模型与配置，再讨论方案效果。
- **标注时间与版本**：模型、框架和协议会变化，结论应有适用范围。
- **尊重来源与隐私**：引用和改编注明出处并遵守原项目许可；示例使用脱敏数据，密钥通过环境变量注入。
