# Agent101 Observatory · 可运行的 Agent 学习工作台

[简体中文](README.md) | [English](README_EN.md)

在浏览器中启动实验，把实际运行事件、固定版本源码和教学解释放在同一张工作台上。

## 启动

需要 **Node.js >=24.9.0** 与 npm。首次安装需要网络下载锁定的 DSH 依赖。在仓库根目录执行：

```sh
npm run setup
npm start
```

打开 <http://127.0.0.1:4173>。后续只需 `npm start`；端口冲突可用 `PORT=4174 npm start`（POSIX shell）。按 Ctrl+C 结束服务。无需构建前端或提供 API Key。首次真实运行通常需要等待进程初始化，页面会保留“运行中”状态。

只看已有证据时，可跳过安装并选择“日志回放”。运行 Web 服务仍需要上述 Node 版本。

## 怎么学

1. **运行第一个任务**：点击“启动实验”，观察真实 DSH 在临时练习目录中读取 README.md 与 package.json。
2. **追踪 Agent 执行链**：点击执行路径或具体事件，查看关联的函数、行号、原始 JSON，以及该条证据能说明什么。选择第 2 个 step，研究 Session 中的工具结果怎样进入下一次请求。
3. **理解插件与 ctx**：运行真实 Cordis，观察消费者 PENDING、依赖就绪后 ACTIVE、资源释放和服务替换。源码来自本仓库的实验，运行库由锁定 Cordis 包自带的源码在内存编译。

“诊断”筛选保留实际子进程 stderr；“导出”下载带运行方式、事件序号与接收时间的 JSONL。手动选择事件会暂停自动跟随；“跟随最新”可恢复。中英文切换保留当前实验与日志。

## 实际执行与证据边界

| 部分 | 实际行为 | 可以证明的范围 |
| --- | --- | --- |
| 真实运行 · 文件任务 | 每次启动新的官方 DSH headless 进程、Agent Loop 和 Shell 工具 | 工具实际读取了练习文件，结果进入后续请求并形成回复 |
| 模型适配器 | 使用本地固定输出，引导读取指定文件，再返回实际工具文本 | 不验证远程模型的推理、提示词理解或任意任务能力 |
| 真实运行 · 插件 | 内存编译已安装 Cordis 包附带的源码，运行共享实验与断言 | 依赖激活、卸载清理、替换后重激活 |
| 日志回放 | 播放仓库已有的实测记录，界面显示播放时间 | 没有启动新的 DSH / Cordis 进程；不能当作本次验证 |
| 源码关联 | 人工核对的事件→函数范围，并在界面解释证据限制 | 教学映射，不是逐行插桩或完整调用栈 |

真实完成需要进程成功退出，并通过文件内容、调用关联和练习文件未被修改等校验。回放完成只表示播放结束，状态不会标为“结果已核对”。原始事件内容保持原样；回放证据中已有的路径/sessionId 规范化见 [实验说明](../labs/dsh/README.md)。

DSH `0.2.2-rc.3`、Cordis `4.1.0`；展示的上游源码固定在 [`38a6a5c`](https://github.com/deepseek-ai/deepseek-harness/tree/38a6a5c965aa99ab525161efb7cc5cf1fe62fced)，快照 SHA-256 和行号范围通过 `npm run check` 校验。上游快照及许可证位于 [sources/](sources/)，教学映射位于 [manifest.json](sources/manifest.json)。运行的发布包与源码 checkout 是两个来源，不声称其构建产物逐字节相同。

## 运行方式与限制

这是**本地 Node 服务 + 浏览器界面**，不是纯静态网站。GitHub Pages 等静态托管不能启动 DSH 子进程。本版仅绑定 loopback，适合个人本机学习，尚未实现公网部署、多用户隔离或登录系统。

浏览器只能选择两种固定实验，不能传入任意命令或路径。每次真实运行创建独立临时工作区与 DSH home，使用既有 `workspace-write` / `never` 配置。它是固定实验的执行边界，不应被当作任意不可信代码的通用隔离服务。

每个服务同时运行一个实验。支持停止、断线重连和页面刷新恢复；内存保留最近 12 次运行，每次最多 1500 条事件，服务重启后不恢复。单次运行超时为 65 秒。日志接收时间是 Web 后端的相对时间，不是函数耗时。真实运行的原始文件保留在系统临时目录 `agent101-web-*`；可从导出日志的 complete 事件查看位置，按需自行清理。

| 问题 | 处理 |
| --- | --- |
| 运行环境未安装 | 在根目录执行 `npm run setup`，刷新；也可先用日志回放 |
| Node 版本过低 | 切换到 Node >=24.9.0 后重启 |
| 已有运行 | 连接已有实验或等待/停止后再启动 |
| 连接中断 | 保留已显示证据，点击重连；不会重新执行任务 |
| 运行失败或超时 | 检查“诊断”和原始 complete 事件；停止/失败后可以重新启动 |
| 运行记录已不存在 | 服务可能已重启或记录已淘汰；启动新实验 |

## 验证与代码入口

```sh
npm test                 # API 边界、状态机、取消、失败、重连和映射
npm run check            # 快照完整性、行号、双语键、设计 token 与语法
npm run build            # 无打包构建；执行可发布源文件检查
npm run verify:runtime   # 实际启动 DSH 与 Cordis，保存验证摘要；需要先 setup
```

- [server.mjs](server.mjs)：本地 HTTP、允许列表、同源校验与 SSE。
- [runtime.mjs](runtime.mjs)：真正启动子进程、收集原始输出、验证结果。
- [runs.mjs](runs.mjs)：运行状态、取消、限额、超时与回放。
- [public/app.mjs](public/app.mjs)：日志选择、源码联动与状态恢复。
- [public/model.mjs](public/model.mjs)：教学事件关联。
- [验证记录](evidence/README.md)：实测结果与已知限制。
